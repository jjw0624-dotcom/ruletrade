# Builder perspective contract

| Perspective | Product question | Source | Editable surface |
|---|---|---|---|
| Summary | What does this strategy intend? | committed semantic projection | none |
| Guide | What can I do next? | committed meaning + capability | typed entry actions |
| Flow | Where does capital go? | capital-routing projection | node layout; validated capital intents |
| Blocky | What logic and actions execute? | committed logic projection + native Working Draft | native Blockly graph |
| Rules | What financial rules are committed? | declarative projection | only proven round-trip fields |
| Code | What are the precise typed semantics? | SemanticProgramV2 | read-only |
| Structure | What objects exist and depend on one another? | definitions + semantic addresses | navigation and supported object operations |

No one-to-one node correspondence is required. A nested Boolean expression has no Flow node. A Group definition has no Blocky instance until referenced. A capital-affecting condition may be summarized in Flow without copying its expression graph.
